<objective>
Per-sensor availability in Home Assistant for HC-SR04 reservoirs, driven by the sensor-error packets the nodes already send.

Purpose: CON (0x7758) with a HC-SR04 that gets no echo sends SENSOR distance_cm=-1 / flags 0x04 every 120 s. `_handle_sensor` logs and returns, the node stays `online` (packets keep arriving), so HA shows the last good reading (102 cm, hours old) as if it were current. After this plan the level/%/volume/distance entities of that sensor go `unavailable` while RSSI, battery and "Último dado" stay visible (last_update shows when the last good reading happened). Two-sensor nodes get independent availability per sensor.

Output: `tools/bridge.py` (helper + dict + small method + two call sites + discovery change) and `tools/test_sensor_availability.py`.

Decision mapping (orchestrator decisions 1-8 -> D-01..D-08): D-01 new retained topic + helper; D-02 publish on error/valid, only on change, always first time; D-03 discovery availability list only for the 4 measurement entities; D-04 heartbeat untouched; D-05 accepted post-deploy unavailability until next valid reading (no mitigation code); D-06 executable assert check; D-07 minimal diff, existing style, other working-tree files untouched; D-08 runtime check done by orchestrator, not by the executor.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node/gateway -> bridge | SENSOR JSON from USB serial, the gateway WiFi mirror (`aguada/gateway/rx`) and wired nodes (`aguada/raw/#`); flags/distance are node-controlled |
| bridge -> MQTT broker -> HA | retained availability + discovery configs consumed by HA |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-t20-01 | Denial of Service | `_set_sensor_avail` publishing every 120 s per sensor | low | mitigate | Publish only on state change via `self._sensor_avail` (Task 1); test asserts repeated states do not republish |
| T-t20-02 | Denial of Service | `publish_discovery` payload validity in HA | medium | mitigate | Measurement entities carry only the `availability` list, others only `availability_topic`; Task 2 test asserts the keys never coexist, so HA does not reject the config and drop the entities |
| T-t20-03 | Spoofing | forged `aguada/raw/#` packet with flags=4 marking a configured sensor offline | low | accept | Pre-existing surface: the same LAN-only, configured-node-gated path can already publish arbitrary readings; availability adds no new capability |
| T-t20-04 | Tampering | `aguada/raw/#` handler runs outside `_dispatch_lock` | low | accept | Race can only cause a duplicate idempotent retained publish of the same state; same accepted pattern as the existing `_seen_seq` cache |
| T-t20-05 | Information Disclosure | new topic `aguada/{node}/{sensor}/availability` | low | accept | Exposes only online/offline for ids already public in `aguada/{node}/{sensor}/state` |
</threat_model>
