  <action>
Create the new PlatformIO project per D-01 and D-02.

**platformio.ini** — a single env `[env:node-cav-eth]` with `platform = atmelavr`, `board = nanoatmega328`, `framework = arduino`, `upload_speed = 57600` (old bootloader), `monitor_speed = 9600`, and `lib_deps` pinned to `uipethernet/UIPEthernet@^2.0.12` and `knolleary/PubSubClient@^2.8`. Per D-01, declare **no** `build_flags` at all — PlatformIO's default `-Os` is what makes this fit; the legacy `-O2` build reached 92% flash. Do not add `build_src_filter`, `-D` defines, or extra libs.

**src/main.cpp** — a single Arduino translation unit. This is an ATmega328: 2 KB RAM, 30 KB usable flash. Hard constraints for the whole file: no `String`, no floating-point math anywhere, no `sprintf`; use `snprintf_P` with `PSTR()` format strings so literals stay in flash; keep every buffer small and stack-local.

Includes: `Arduino.h`, `UIPEthernet.h`, `PubSubClient.h`, `avr/wdt.h`.

Compile-time configuration, all as `#define`/`static const`:
- `DEBUG` defaults to `0`. Define `DBG(...)`/`DBGLN(...)` macros that expand to nothing when `DEBUG` is 0, and to `Serial.print`/`Serial.println` when 1; guard `Serial.begin(9600)` in `setup()` with the same macro so a release build links no serial code at all (D-02 flash savings).
- Pins: `TRIG_PIN` 6, `ECHO_PIN` 7 (ECHO is D7 per the user's explicit decision — not D5). The ENC28J60 uses hardware SPI D11/D12/D13 with CS on D10, which is UIPEthernet's default; no CS constant is needed.
- Identity: `NODE_ID_STR` `"0xEE02"`, `SENSOR_ID` `1`, MQTT client id `"aguada-0xEE02"`, publish topic `"aguada/raw/0xEE02/1"` held in a `static const char TOPIC[]` in RAM (PubSubClient's `publish()` needs a RAM pointer).
- Network: MAC `{0xAA,0xBB,0xCC,0xDD,0xEE,0x02}`, static `IPAddress` 192.168.0.202, gateway and DNS 192.168.0.1, subnet 255.255.255.0, broker 192.168.0.101 port 1883. No DHCP, no EEPROM, no offset config, no captive portal.
- Timing/filter: `MEASURE_INTERVAL_MS` 30000UL, `FORCE_SEND_MS` 120000UL, `DELTA_CM` 2, `SAMPLES` 5, `MIN_VALID` 3, `DIST_MIN_CM` 2, `DIST_MAX_CM` 450, `PULSE_TIMEOUT_US` 30000UL, `MQTT_RETRY_MS` 5000UL, `MEAS_FAIL_LIMIT` 3, `FAIL_ETH_REINIT` 10, `FAIL_HARD_RESET` 20.

Globals: an `EthernetClient` wrapped by a `PubSubClient`, plus `uint16_t seq` (0), `uint16_t lastSent` initialised to `0xFFFF` as a never-sent sentinel, `uint32_t lastMeasureMs`/`lastSendMs`/`lastMqttTryMs`, and `uint8_t measFail`/`mqttFail`.

Watchdog reset safety (critical, D-02): the classic Nano bootloader implied by `upload_speed = 57600` does **not** clear the WDRF flag, so a deliberate watchdog reset would otherwise boot-loop the node forever. Add a function declared `__attribute__((naked, used, section(".init3")))` that zeroes `MCUSR` and calls `wdt_disable()`; it runs before `main()` and makes the forced-reset recovery path survivable.

Functions:
- `uint16_t readOnce()` — drive TRIG low 2 µs, high 10 µs, low; `pulseIn(ECHO_PIN, HIGH, PULSE_TIMEOUT_US)`; return 0 when the pulse times out, otherwise integer `duration / 58UL` narrowed to `uint16_t`. No float speed-of-sound math.
- `uint16_t measure()` — take up to `SAMPLES` readings about 60 ms apart into a `uint16_t buf[SAMPLES]`, keeping only values in `[DIST_MIN_CM, DIST_MAX_CM]`; call `wdt_reset()` inside the sampling loop. Return 0 if fewer than `MIN_VALID` samples survived; otherwise insertion-sort the valid prefix and return the median element `buf[n/2]`.
- `void netBegin()` — `Ethernet.begin(mac, ip, dns, gw, subnet)`, used both at boot and by the escalation path.
- `bool mqttEnsure()` — return true immediately when already connected; otherwise throttle attempts to one per `MQTT_RETRY_MS`, `wdt_reset()` around the connect call, and attempt `connect(CLIENT_ID)`. On success zero `mqttFail` and return true. On failure increment `mqttFail`, then escalate per D-02: at `FAIL_HARD_RESET` call `wdt_enable(WDTO_15MS)` and spin in an empty infinite loop to force a reset; at exactly `FAIL_ETH_REINIT` re-run `netBegin()`. Return false.
- `void publishReading(uint16_t cm, uint8_t flags)` — build the payload with `snprintf_P` into a `char payload[160]` using a `PSTR` format that emits, in this exact key order, `type` (string `sensor`), `node_id` (string `0xEE02`), `sensor_id` (1), `distance_cm` (`%u`), `rssi` (0), `vbat` (-1), `flags` (`%u`), `seq` (`%u`). Every numeric field is a plain integer — no decimals, no level/percent/volume fields; that math belongs to bridge.py. Publish to `TOPIC` and post-increment `seq`. PubSubClient 2.8's default 256-byte buffer comfortably holds this ~110-byte payload plus the 19-byte topic, so do **not** call `setBufferSize()` (it would cost scarce RAM).

`setup()`: init debug serial (guarded), `pinMode` TRIG output / ECHO input, `netBegin()`, `mqtt.setServer(...)`, `mqtt.setSocketTimeout(4)` **before** any connect attempt so a stalled broker cannot outlast the watchdog (D-02), then `wdt_enable(WDTO_8S)`. Seed the millis timestamps.

`loop()`: `wdt_reset()` first, then `mqttEnsure()` and `mqtt.loop()`. When `MEASURE_INTERVAL_MS` has elapsed (compare with unsigned `millis()` subtraction so the ~49-day rollover is harmless), stamp `lastMeasureMs` and call `measure()`. On a zero result increment `measFail`; once it reaches `MEAS_FAIL_LIMIT`, publish an error packet with `distance_cm` 65535 and `flags` 4 (bridge.py already treats `flags & 0x04` as a sensor error), stamp `lastSendMs`, and reset `measFail` to 0 so errors are not re-emitted every cycle. On a valid reading reset `measFail`, then send when any of these hold: `lastSent` is still the `0xFFFF` sentinel, the unsigned absolute difference between the reading and `lastSent` is at least `DELTA_CM`, or `FORCE_SEND_MS` has elapsed since `lastSendMs`. Only publish when MQTT is actually connected; on a successful publish update `lastSent` and `lastSendMs`.

Do not publish `aguada/0xEE02/status` from the node — bridge.py's `NodeTracker` owns that topic (D-02).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN host → MQTT broker | Any device on 192.168.0.0/24 can publish to `aguada/raw/#`; the broker is plaintext 1883 with no per-client ACL configured. |
| MQTT broker → bridge.py | New surface: bridge.py now accepts sensor data from a network topic, not only from the physically attached serial gateway. |
| HC-SR04 → node firmware | Untrusted analogue timing input parsed into a `uint16_t` distance on a 2 KB-RAM MCU. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-L28-01 | Spoofing | `_on_mqtt_message` raw branch, tools/bridge.py | medium | mitigate | Task 2 gates the raw path on `self._configured_nodes` membership before calling `_handle_sensor`, so an arbitrary `node_id` cannot reach `NodeTracker.seen()` and mint a retained `aguada/{id}/status = online` topic. Injection of a *plausible* reading for a configured node remains possible on a trusted LAN — see T-L28-03. |
| T-L28-02 | Denial of Service | `_on_mqtt_message`, paho callback thread | medium | mitigate | Task 2 wraps `json.loads` (existing), adds a non-`dict` payload rejection, and wraps `_handle_sensor` in `try/except Exception` + `log.exception`, mirroring `dispatch()`. A malformed or hostile payload logs and is dropped instead of killing the MQTT loop thread and silently deafening the whole bridge. |
| T-L28-03 | Tampering | MQTT transport, node ↔ broker | low | accept | ATmega328 with UIPEthernet cannot do TLS in 30 KB of flash, and the existing gateway/bridge deployment is already plaintext MQTT on an isolated industrial LAN. Broker-side authentication and a topic ACL restricting `aguada/raw/#` writes to the node's credentials are the correct fix and belong to `tools/mosquitto/` configuration, outside this task. Task 3's README documents the exposure so it is a known, recorded risk rather than a silent one. |
| T-L28-04 | Information Disclosure | `aguada/raw/#` payloads | low | accept | Payloads carry only reservoir distance readings — no credentials, no PII. Plaintext exposure on the LAN has no meaningful confidentiality impact. |
| T-L28-05 | Denial of Service | node firmware watchdog path | medium | mitigate | The `wdt_enable(WDTO_15MS)` forced-reset escalation is self-bricking on the classic Nano bootloader, which does not clear WDRF — the node would boot-loop out of the field permanently. Task 1 adds the `.init3` `MCUSR = 0; wdt_disable();` preamble so the recovery path actually recovers. `mqtt.setSocketTimeout(4)` keeps a stalled broker from tripping the 8 s watchdog during a normal connect. |
| T-L28-SC | Tampering | PlatformIO dependency `uipethernet/UIPEthernet` | low | mitigate | Not an npm/pip/cargo install, so the package-legitimacy checkpoint protocol does not apply; PubSubClient@^2.8 is already an established dependency of `firmware/gateway`. UIPEthernet is new: pin it to `^2.0.12` as specified, and confirm the package page on registry.platformio.org resolves to the known `UIPEthernet` library before the first build. Do not let PlatformIO resolve an unpinned or differently-owned package. |
