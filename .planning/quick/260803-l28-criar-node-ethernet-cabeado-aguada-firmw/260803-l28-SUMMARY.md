# Quick Task 260803-l28: Wired Ethernet Node (node-eth) Summary

**New `firmware/node-eth/` PlatformIO project (Arduino Nano + ENC28J60 + HC-SR04) publishing gateway-shaped sensor JSON to `aguada/raw/0xEE02/1`, plus a `tools/bridge.py` extension routing that topic through the existing `_handle_sensor` pipeline for free reservoir math, HA Discovery and tracking.**

## Accomplishments

- New self-contained PlatformIO project `firmware/node-eth/` targeting `env:node-cav-eth` (`nanoatmega328`), building clean with no `build_flags` override — Flash 73.7% (22640/30720B), RAM 56.9% (1166/2048B)
- Node firmware publishes integer-only, gateway-shaped JSON (`type`, `node_id`, `sensor_id`, `distance_cm`, `rssi`, `vbat`, `flags`, `seq`) via `snprintf_P`/`PSTR` with zero `String`, `sprintf`, or floating-point code
- Watchdog-safe forced-reset recovery via an AVR `.init3` `MCUSR = 0; wdt_disable();` preamble, so the classic Nano bootloader's WDRF quirk cannot boot-loop the node
- `tools/bridge.py` now subscribes to `aguada/raw/#`, gates unknown node ids before `_handle_sensor` (avoiding phantom retained `online` statuses via `NodeTracker.seen()`), and wraps the handler call in `try/except` + `log.exception` so a bad packet can't kill the MQTT callback thread
- `firmware/node-eth/README.md` documents pinout, the ENC28J60 3.3V power requirement, static network config, venv-based build/upload commands, and troubleshooting steps

## Decisions Made

- No `build_flags` in `platformio.ini` — relying on PlatformIO's default `-Os` per D-01, since a legacy `-O2` build had reached 92% flash usage
- Kept `NODE_ID_STR`/`CLIENT_ID`/`TOPIC` as compile-time `#define`s concatenated directly into the `PSTR()` payload format string, avoiding a separate runtime string-copy step and any extra flash/RAM
- Allowlist check (`self._configured_nodes`) happens in `_on_mqtt_message` *before* `_handle_sensor` is called, not delegated to `_handle_sensor` itself, because `_handle_sensor` calls `NodeTracker.seen()` (which publishes a retained `online` status) before its own reservoir lookup — an unchecked call would let a spoofed node_id mint a phantom status topic
- `dispatch()`, `_handle_sensor`, and `_mark_gateway_seen()` left byte-identical; the raw-MQTT path never calls `_mark_gateway_seen()` since a wired node is not the serial gateway
