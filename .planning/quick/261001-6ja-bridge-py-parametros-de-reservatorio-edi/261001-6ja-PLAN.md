<objective>
Reservoir parameters (altura útil, offset do sensor, volume máximo) become editable from Home Assistant, persist to `tools/reservoirs.yaml`, and implausible HC-SR04 readings are treated as sensor errors.

User flow: in HA the operator opens device "CAV" -> section "Configuração" -> box "Castelo de Incêndio - Altura útil" shows 450 -> types 460 -> Enter. HA publishes `460` on `aguada/0XC9C4/1/config/level_max_cm/set`; bridge validates, applies it to the next reading immediately, rewrites only that line in reservoirs.yaml (comments kept), republishes the retained config state and the box stays at 460. An invalid value is logged and the state is republished, so the box snaps back to the current value. The boxes stay editable when the node is offline (no availability). Syncing to aguada-web (`tools/sync_reservoirs.sh`) stays a manual step for the user (D-06).

Purpose of the out-of-range rule: 2026-09-30 CIE2 sent 299 cm with level_max 240 + offset 10; calculate() clamped it to 0 % and HA fired a false critical-level alarm. With the rule the sensor goes unavailable instead.

Output: `tools/bridge.py` (constants, YAML text editor, discovery function, topic helper, two Bridge methods, three call sites) and new `tools/test_reservoir_config.py`.

Decision mapping (user-confirmed requirements 1-9 -> D-01..D-09): D-01 number discovery per HC-SR04 reservoir; D-02 retained config state topic, published on connect and after each change; D-03 command topic, subscribe, validation, in-memory update, INFO log; D-04 textual atomic YAML persistence, no new deps; D-05 out-of-range reading = sensor error; D-06 minimal diff, file style, ANI/relay/env/gateway untouched, no sync_reservoirs.sh; D-07 executable self-check on a temp copy; D-08 venv python + regression tests; D-09 other-session files untouched, explicit-path staging, no service restart.
