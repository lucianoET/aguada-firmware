## Pattern Assignments

### `firmware/gps_tracker/src/i2c_bus.cpp/.h` (utility, boot-scan + health)

**Analog:** `firmware/node/src/ani_sensor.cpp` / `.h`

**Imports pattern** (`ani_sensor.cpp` lines 1-5):
```cpp
#include "ani_sensor.h"
#include <Wire.h>
#include <Adafruit_AHTX0.h>
#include <ScioSense_ENS160.h>
#include <esp_log.h>
```
New file should mirror this shape: `#include "i2c_bus.h"`, `<Wire.h>`, `<esp_log.h>`; no sensor-specific driver includes belong here (those live in the per-sensor modules).

**Boot scan pattern** (`ani_sensor.cpp` lines 18-33, cited verbatim in RESEARCH.md Code Examples):
```cpp
bool ani_init(uint8_t sda_pin, uint8_t scl_pin) {
    s_sda = sda_pin;
    s_scl = scl_pin;

    Wire.begin(sda_pin, scl_pin);
    Wire.setClock(50000);
    delay(50);

    ESP_LOGI(TAG, "I2C scan (sda=%d scl=%d):", sda_pin, scl_pin);
    for (uint8_t addr = 0x08; addr <= 0x77; addr++) {
        Wire.beginTransmission(addr);
        if (Wire.endTransmission() == 0) {
            ESP_LOGI(TAG, "  found 0x%02X", addr);
        }
    }
    ...
```
Adapt: use `DEFAULT_I2C_CLOCK_HZ` (400kHz per RESEARCH.md, not the AirQ node's conservative 50kHz) instead of hardcoded `50000`.

**Clock-restore-after-library-init pattern** (`ani_sensor.cpp` lines 56-58) — **critical, must copy exactly**:
```cpp
// Restore correct pins and clock after library Wire.begin() calls
Wire.begin(sda_pin, scl_pin);
Wire.setClock(50000);
```
Every per-sensor driver's own `.begin()` (U8g2, DFRobot_QMC5883, Adafruit HTU21DF) may silently reset the bus clock (Pitfall 2 in RESEARCH.md) — `i2c_bus` should re-assert `DEFAULT_I2C_CLOCK_HZ` after each module init, and `mag_sensor`/`env_sensor`/`accel_sensor`'s own `.poll()` should defensively re-set it too, exactly like `ani_read()` does at line 77 (`Wire.setClock(50000);`) before every read.

**Health-flag pattern** (`ani_sensor.h` lines 14-22, `ani_sensor.cpp` lines 12-13, 63-66):
```cpp
static bool s_aht_ok = false;
static bool s_ens_ok = false;
...
void ani_status(bool *aht_ok, bool *ens_ok) {
    if (aht_ok) *aht_ok = s_aht_ok;
    if (ens_ok) *ens_ok = s_ens_ok;
}
```
`i2c_bus` should generalize this to 4 independent `bool` online flags (one per module: display, accel, mag, env) plus D-13's consecutive-error counters and a ~10s retry timer per module — this is new surface `ani_sensor` doesn't need (AirQ has no runtime retry requirement), so extend rather than copy verbatim here.

**Anti-pattern to explicitly avoid** (`ani_sensor.cpp` lines 107-115):
```cpp
uint32_t deadline = millis() + 1000UL;
while (!s_ens.available() && millis() < deadline) {
    delay(10);
}
```
Do NOT port this blocking wait into any Phase 01.1 driver — RESEARCH.md Pitfall 1 flags this exact loop as the anti-pattern that would starve the GPS UART ring buffer. Poll a "ready" flag across `loop()` iterations instead of spinning inside one call.

### `firmware/gps_tracker/src/accel_sensor.cpp/.h` (driver, hand-rolled raw I2C)

**Analog:** No existing repo analog for hand-rolled raw-I2C register access (the repo's other I2C sensors use libraries). Follow RESEARCH.md Architecture Patterns Pattern 4 directly, and reuse `ani_sensor.h`'s init/health-flag *shape* (a plain C-style `bool xxx_init(...)`, a small POD reading struct, a `bool xxx_ok()` accessor):

```cpp
// Source: RESEARCH.md Pattern 4, register addresses cross-checked against
// InvenSense MPU-6050 register map via community tutorials.
bool mpu6050Init(uint8_t addr) {
    Wire.beginTransmission(addr);
    Wire.write(0x75);                 // WHO_AM_I
    if (Wire.endTransmission(false) != 0) return false;
    Wire.requestFrom(addr, (uint8_t)1);
    if (!Wire.available() || Wire.read() != 0x68) return false;

    Wire.beginTransmission(addr);
    Wire.write(0x6B); Wire.write(0x00);   // PWR_MGMT_1 = 0 -> wake from sleep
    return Wire.endTransmission() == 0;
}

float mpu6050AccelMagnitudeG(uint8_t addr) {
    Wire.beginTransmission(addr);
    Wire.write(0x3B);                 // ACCEL_XOUT_H
    Wire.endTransmission(false);
    Wire.requestFrom(addr, (uint8_t)6);
    int16_t ax = (Wire.read() << 8) | Wire.read();
    int16_t ay = (Wire.read() << 8) | Wire.read();
    int16_t az = (Wire.read() << 8) | Wire.read();
    float gx = ax / 16384.0f, gy = ay / 16384.0f, gz = az / 16384.0f;
    return sqrtf(gx*gx + gy*gy + gz*gz);
}
```

**Header shape to copy** (`ani_sensor.h` as template):
```cpp
#pragma once
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    float magnitude_g;
    bool  valid;
} AccelReading;

bool accel_init(uint8_t addr);
AccelReading accel_read(void);
bool accel_ok(void);
```

**Error handling:** treat `Wire.endTransmission() != 0` or `Wire.requestFrom()` returning fewer bytes than requested as a failed read — feed into `i2c_bus`'s per-module consecutive-error counter (D-13), same contract as `ani_sensor`'s `s_aht_ok`/`s_ens_ok` flags but reported through the shared bus-manager instead of locally, since D-13's retry/offline policy is cross-cutting.

#include <Preferences.h>

    magPrefs.begin("magcal", false);

    magPrefs.putFloat("xMax", xMax);

### `firmware/gps_tracker/src/env_sensor.cpp/.h` (driver, Adafruit HTU21DF wrapper)

**Analog:** `ani_sensor.cpp/.h` — closest structural match (init + health flag + read-with-fallback-to-last-known-value):
```cpp
static float s_last_temp = 25.0f;
static float s_last_hum  = 50.0f;
...
if (aht_ok) {
    r.temp_c  = temp_evt.temperature;
    r.hum_pct = hum_evt.relative_humidity;
    s_last_temp = r.temp_c;
    s_last_hum  = r.hum_pct;
} else {
    r.temp_c  = s_last_temp;
    r.hum_pct = s_last_hum;
}
```
Reuse this last-known-value fallback shape for `env_sensor` so a transient HTU21D read failure doesn't blank the display field.

**Critical deviation from the analog (Pitfall 6):** do NOT wait on `Adafruit_HTU21DF::readTemperature()`/`readHumidity()` back-to-back inside a tight budget — each internally blocks ~50ms (`delay(50)`), ~100ms combined. Schedule this module's `poll()` via `DEFAULT_HTU21_POLL_MS` (RESEARCH.md suggests 3000-5000ms) using the Pattern 1 timer below, never call it every `loop()` iteration.

### `firmware/gps_tracker/src/cadence.cpp/.h` (MODIFIED — add `onAccelWake()`)

**Analog:** itself — extend the existing class, do not bypass it.

**Existing contract to preserve** (`cadence.h` lines 4-8, must be updated, not silently violated):
```cpp
// Cadence is a pure speed-driven, hysteresis-debounced pacing decision over
// a stream of gate-accepted Fix snapshots. It never touches the parser, the
// UART, or Serial (see cadence.cpp) -- the only call site is main.cpp's
// single GateResult::ACCEPT branch, never anywhere else, so an ungated fix

```
Per RESEARCH.md Pitfall 4: add an explicit `onAccelWake()` method alongside `onGatedFix()`, and update this comment to document both call sites and their asymmetric authority — accel can only promote `STATIONARY -> MOVING`; only `onGatedFix()` (GPS-gated) may demote `MOVING -> STATIONARY`. The demotion path (`onGatedFix()`'s hysteresis/debounce block, `cadence.cpp` lines 52-64) stays unchanged.

**State transition shape to mirror** (`cadence.cpp` lines 39-51, the STATIONARY→MOVING branch) — `onAccelWake()` should perform the same bookkeeping (`stateEnteredMs_`, `lastTransitionSpeedKmh_`, `lastTransitionElapsedS_`, `stateChanged_ = true`) as this existing branch, just triggered by the accel magnitude threshold instead of `movingStreak_ >= DEFAULT_GPS_DEBOUNCE_FIXES`.

## Shared Patterns

### Non-blocking `millis()`-based per-peripheral scheduling
**Source:** `firmware/gps_tracker/src/main.cpp` lines 31, 410-411 (existing `lastHealthMs`/`DEFAULT_GPS_HEALTH_PERIOD_MS` block), generalized in RESEARCH.md Architecture Patterns Pattern 1.
**Apply to:** `accel_sensor`, `mag_sensor`, `env_sensor`, `display` — every peripheral poll/render call in `main.cpp`'s `loop()`. Never call any of these unconditionally on every `loop()` pass.

### I2C boot scan + graceful degradation (no missing module blocks anything)
**Source:** `firmware/node/src/ani_sensor.cpp` lines 26-33 (scan loop), lines 18-61 (`ani_init()`'s independent per-sensor `.begin()`/health-flag pattern).
**Apply to:** `i2c_bus.cpp` (the shared scan), and each of `accel_sensor`/`mag_sensor`/`env_sensor`/`display`'s own `init()` — each must independently succeed/fail without gating the others or the GPS pipeline (D-12).

### Wire clock restore-after-library-init
**Source:** `firmware/node/src/ani_sensor.cpp` lines 56-58 and line 77 (`Wire.setClock(50000)` re-asserted after every library `.begin()` and before every read).
**Apply to:** `i2c_bus.cpp` after each module's `.begin()`, and defensively inside each sensor module's own `poll()`/`read()` — using `DEFAULT_I2C_CLOCK_HZ` (400kHz) instead of the AirQ node's 50kHz.

### `#ifndef`-guarded `DEFAULT_*` build-flag constants
**Source:** `firmware/gps_tracker/include/gps_config.h` (entire file convention).
**Apply to:** every new tunable constant introduced by this phase — never hardcode a threshold/pin/interval in a `.cpp` file.

### Cadence single-call-site contract, deliberately extended (not bypassed)
**Source:** `firmware/gps_tracker/src/cadence.h` lines 4-8 (documented invariant) + `cadence.cpp` lines 27-64 (`onGatedFix()` state-transition bookkeeping shape).
**Apply to:** the new `onAccelWake()` entry point and its call site in `main.cpp` — must be documented as a second, asymmetric-authority call site, not a silent side-entry.

### Avoid: blocking `while(!ready) delay(N)` sensor-wait loops
**Source (anti-pattern):** `firmware/node/src/ani_sensor.cpp` lines 107-115 (`while (!s_ens.available() && millis() < deadline) { delay(10); }`, up to 1000ms).
**Apply to:** explicitly avoid in `accel_sensor`, `mag_sensor`, `env_sensor` — RESEARCH.md Pitfall 1 identifies this exact repo pattern as the one to NOT port, since it would starve the ~266ms GPS UART buffer window.
