## Accomplishments
- Added `GpsReader::satsInView()`: three `mutable TinyGPSCustom` members (GPGSV/GLGSV/GNGSV field 3, registered in the constructor) covering both supported modules' talker IDs, returning the freshest (age < `DEFAULT_GPS_FRESH_MS`) value or 0 — the only new accessor authorized to read GSV data, preserving `GpsReader`'s exclusive ownership of the TinyGPSPlus parser
- Built `display.h`/`.cpp`: a full-buffer, hardware-I2C U8g2 SSD1306 driver with address fallback (`DEFAULT_OLED_ADDR` then `_ALT`), a 19-field `DisplayState` contract, and `render()` drawing either the D-01 dense screen (fix/sats/HDOP, speed with unit label, heading with cardinal + source marker, temp/hum, cadence + accel magnitude, uptime + compact offline-module letters) or the D-03 acquisition screen (NO FIX + sats in view + NMEA-reception indicator + uptime, with heading/temp-hum/accel still live) — exactly one `sendBuffer()` transfer per call, zero calls into any other Fase 01.1 driver
- Wired `main.cpp`: `buildDisplayState()` bridges `lastFix`/`cadence`/`mag_sensor`/`env_sensor`/`accel_sensor`/`i2c_bus` into one frame per render; `speedInDisplayUnit()`/`speedUnitLabel()` resolve km/h vs. knots purely from `DEFAULT_SPEED_UNIT` (D-04); the render block sits after every peripheral poll and before `[HEALTH]`, firing on `DEFAULT_DISPLAY_REFRESH_MS` with an 80%-elapsed-and-fresh-fix anticipation so the frame never drifts a full second behind the fix (D-02); `display::begin()` is wired into `setup()` and `i2cRecoverTick()`'s `DISPLAY` case; `[HEALTH]` gained `sats_view=`/`disp_addr=` with every prior field intact

## Decisions Made
- `TinyGPSCustom` members for GSV field 3 are registered in `gps_reader.cpp`'s constructor initializer list (not header in-class initializers), matching the plan's literal wording and keeping `GpsReader`'s default-constructible contract intact for `main.cpp`'s existing global instance
- The three GSV members are `mutable` so the `const`-qualified `satsInView()` can call `TinyGPSCustom::value()` (which mutates its own `updated` flag as a side effect) without violating constness
- `speedInDisplayUnit()`/`speedUnitLabel()` use a plain `if (DEFAULT_SPEED_UNIT == 0)` comparison (compiler-folded, since the macro is a compile-time constant) instead of `#if` preprocessor branching — simpler code, identical compile-time resolution, still decided purely from the build flag and never from runtime state
- The plan's third automated verify command used a `--project-option="build_flags=..."` pio CLI flag that this environment's PlatformIO version does not support (confirmed via `pio run --help`); substituted the equivalent `PLATFORMIO_BUILD_FLAGS` environment variable to force the `DEFAULT_SPEED_UNIT=1` rebuild, which compiled successfully (exit 0)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Plan's verify command used a nonexistent `pio` CLI flag**
- **Found during:** Task 2 (running the third automated verify command)
- **Issue:** The plan specified `pio run -e esp32-c3-supermini --project-option="build_flags=..."` to rebuild with `-DDEFAULT_SPEED_UNIT=1`, but this PlatformIO installation's CLI has no `--project-option` flag (`pio run --help` lists only `-e/-t/--upload-port/--monitor-port/-d/-c/-j/-a/--disable-auto-clean/--list-targets/-s/-v/-h`).
- **Fix:** Used the equivalent `PLATFORMIO_BUILD_FLAGS="-DDEFAULT_SPEED_UNIT=1"` environment variable (a documented PlatformIO override mechanism) to append the flag for a one-off rebuild, without touching `platformio.ini`.
- **Files modified:** None (build-invocation only, no source change).
