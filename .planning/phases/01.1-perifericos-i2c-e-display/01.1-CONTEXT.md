# Phase 01.1: Periféricos I2C e Display - Context

**Gathered:** 2026-08-03
**Status:** Ready for planning

<domain>
## Phase Boundary

O firmware `firmware/gps_tracker/` ganha um barramento I2C compartilhado (GPIO6 SDA / GPIO7 SCL no ESP32-C3 SuperMini) com 4 módulos: **OLED SSD1306 128×64 (0x3C)** para status ao vivo, **MPU6050 (0x68)** para detecção de movimento alimentando a cadência, **HMC5883L (0x1E)** para rumo, **HTU21D (0x40)** para temperatura/umidade. Tudo observável na bancada (OLED + serial USB). Não inclui: flash logging (Fase 2), WiFi/sync (Fase 3), protocolo v3/ESP-NOW (v2), deep sleep (v2). O rastreamento GPS existente (gps_reader → fix_gate → cadence) continua funcionando intacto — periféricos nunca bloqueiam o GPS.

</domain>

<decisions>
## Implementation Decisions

### Display (SSD1306)
- **D-01:** Tela única densa — fix/sats/HDOP, velocidade, rumo, temp/umid, estado da cadência (MOVING/STOPPED), tudo visível de uma vez. Sem paginação, sem botões.
- **D-02:** Refresh a 1 Hz, alinhado ao fix do GPS.
- **D-03:** Sem fix (cold start): tela de aquisição ao vivo — "NO FIX" + sats em vista + uptime + leituras dos sensores que JÁ estão vivos (temp/umid, rumo, movimento). Confirma a fiação enquanto espera fix.
- **D-04:** Unidade de velocidade selecionável por build flag (`DEFAULT_SPEED_UNIT`), km/h default, nós (kt) para embarcação. Rumo em graus + cardinal.

### MPU6050 → cadência
- **D-05:** Papel híbrido: accel detecta parado→movimento instantaneamente (GPS demora vários fixes para ver velocidade); GPS speed continua sendo a autoridade para movimento→parado. Retomada rápida sem logar pontos de drift.
- **D-06:** Detecção por polling do accel via I2C (magnitude + threshold/debounce em software). Sem fio INT nesta fase.
- **D-07:** Accel apenas — giroscópio não usado nesta fase.

### Rumo (HMC5883)
- **D-08:** Fonte de rumo mesclada por velocidade: bússola quando parado/lento (GPS course é lixo abaixo de ~3 km/h), GPS course quando em movimento.
- **D-09:** Calibração hard-iron por comando serial ("cal" no USB serial → girar o módulo → offsets min/max persistidos em NVS). Recalibrável após instalação sem recompilar.
- **D-10:** Montagem plana assumida no v1 — sem tilt compensation. Declinação magnética via build flag `DEFAULT_MAG_DECLINATION` (0 default).
- **D-11:** Muitos GY-271 vêm com QMC5883L (0x0D) em vez de HMC5883L (0x1E) — o firmware deve detectar e suportar ambos.

### Papéis dos sensores & política de falha
- **D-12:** Degradação graciosa total: scan I2C no boot; módulo ausente → recurso desligado, indicado no display/serial, resto roda. Rastreamento GPS nunca bloqueado por falha de periférico. Qualquer subconjunto dos 4 módulos funciona.
- **D-13:** Falha em runtime (fio solto, erro de barramento): marcar offline após N erros consecutivos, retry de re-init a cada ~10 s, volta sozinho quando religado.
- **D-14:** HTU21: display + serial apenas nesta fase. Integração com log/MQTT vem nas Fases 2/3.

### Claude's Discretion
- Thresholds de movimento (magnitude do accel, janela de debounce, tempo de "quieto") — decidir no research/planning, expor como constantes `DEFAULT_*` em build_flags (convenção do repo).
- Bibliotecas dos módulos (U8g2 vs Adafruit SSD1306, driver MPU/HMC/QMC/HTU) — decidir no research; preferir leve e consistente com o stack PlatformIO/Arduino existente.
- Layout exato da tela densa (fontes, posições) e formato do log serial de bancada.
- Detalhes de retry/backoff I2C e recuperação de barramento.
- Frequência de leitura de cada sensor (HTU21 pode ser lento, ~alguns segundos; accel precisa ser rápido para wake).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `firmware/node/src/ani_sensor.*` — padrão I2C init + graceful degradation do nó AirQ (referência conceitual; projetos separados).
- `firmware/gps_tracker/src/cadence.*` — API `onGatedFix()` / classificação por velocidade; ponto de acoplamento do accel-wake.
- Simulador de bancada `GPS_BENCH_SIM` (BENCH.md) — estender para exercitar cadência com movimento simulado se útil.

### Established Patterns
- Constantes configuráveis via `#define DEFAULT_*` em build_flags.
- Valores crus no firmware; matemática no servidor (rumo mesclado é exceção justificada: é UX de display local).
- I2C em GPIO6/7 é convenção do repo (AirQ).

### Integration Points
- `cadence` — accel-wake entra como sinal de transição parado→movimento (D-05) sem quebrar a autoridade do GPS speed.
- `main.cpp` loop — leituras dos sensores + refresh do display 1 Hz.
- OLED I2C substitui o plano TFT ST7735 SPI (HW-02) — GPIO1–5 ficam livres no C3.

</code_context>

<specifics>
## Specific Ideas

- Usuário vai montar a bancada AGORA pela seção "Fase 01.1" do `gps_tracker_pinout.md` — firmware deve casar exatamente com essa fiação (GPIO6/7, endereços 0x3C/0x68/0x1E/0x40).
- Módulos separados no barramento (não é shield integrado) — cada um pode estar presente ou não; scan no boot detecta o que existe.

</specifics>

<deferred>
## Deferred Ideas

- Tilt compensation da bússola (adernagem de embarcação) — upgrade futuro sobre D-10.
- Fio INT do MPU6050 como wake source de deep sleep — junto com PWR-03 (v2).
- Temp/umid (HTU21) e rumo no log de flash / MQTT — Fases 2/3.
- Botão (GPIO9) para paginação do display — se a tela única ficar apertada.
