# Phase 01.1 Plan 03: Compass and Environment Peripherals Summary

**DFRobot_QMC5883 compass (auto-detecting HMC5883L/QMC5883L, hard-iron-calibrated heading persisted in NVS, speed-blended against GPS course) plus an alternating-read HTU21D temp/humidity wrapper and the new multi-character "cal" serial command, all wired into main.cpp alongside the Fase 1 pipeline without disturbing it.**

- **Completed:** 2026-08-03T09:48:43Z

## Accomplishments
- Built `mag_sensor.h`/`.cpp`: probes `i2c_bus::present()` in HMC/QMC/VCM order to pick the responding address, constructs `DFRobot_QMC5883` with that exact address (required because the library's own auto-detect scan and its subsequent register reads use different address sources internally), classifies the chip via `isHMC()`/`isQMC()`/`isVCM()`, and computes heading locally via `atan2f` on hard-iron-corrected X/Y axes plus `DEFAULT_MAG_DECLINATION` — never via the library's own `getHeadingDegrees()`, which neither applies calibration offsets nor returns a usable value
- Implemented hard-iron calibration (D-09): `calStart()`/`calFinish()`/`calAbort()` capture min/max X/Y over a full rotation, `calFinish()` rejects a capture whose amplitude is below an anti-degenerate floor (keeping the previous calibration), and a valid capture is persisted to `Preferences` namespace `"magcal"` (4 floats + a `"set"` marker), reloaded at boot
- Built `env_sensor.h`/`.cpp`: alternates `readTemperature()`/`readHumidity()` one per `poll()` call (halving the ~100ms combined blocking cost against the ~266ms GPS UART buffer budget), treats a `NAN` result as a failed read without blanking the last known values, reports through `i2c_bus`
- Wired both peripherals into `main.cpp`: scheduled polls on `DEFAULT_MAG_POLL_MS`/`DEFAULT_HTU21_POLL_MS`, a bounded 8-byte multi-character parser `calHandleChar()` consulted before the Fase 1 single-char hotkey dispatch (unchanged), real chip re-init in `i2cRecoverTick()`'s `MAG`/`ENV` cases, and an extended `[HEALTH]` line (`hdg=`/`hdg_src=`/`mag_chip=`/`temp=`/`hum=`) plus a `[CAL] active` progress line during capture

## Decisions Made
- `DFRobot_QMC5883` is constructed with the address `i2c_bus::present()` actually detected, not the library's own default (0x0C) — the library's `begin()` auto-detects `ICType` by probing its own hardcoded HMC/QMC/VCM addresses, but every subsequent register read uses the constructor-supplied address, so the two must match or reads silently target the wrong device
- Added `mag_sensor::calRange()` beyond Task 1's originally-declared 13-function contract, because Task 3's bench-visible `[CAL] active` progress line needs read access to the in-progress capture's live min/max without duplicating that accumulator state in `main.cpp`
- A lightweight `Wire.beginTransmission`/`endTransmission` probe precedes the actual library read in both `mag_sensor::poll()` and `env_sensor::poll()`, purely so a genuine disconnect routes through `i2c_bus::reportError()` (D-13) — neither library's read path (`readRaw()`, `readTemperature()`/`readHumidity()`) signals a missing device on its own
