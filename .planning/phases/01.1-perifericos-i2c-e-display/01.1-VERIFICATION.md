### Gap-Closure Verification (this pass)

Both blocking gaps from the previous VERIFICATION.md were re-checked by reading the actual
current source (not by trusting `01.1-REVIEW-FIX.md`'s narrative), and by re-running both
PlatformIO builds fresh in this session.

**Gap 1 (CR-01) — `i2cRecoverTick()` forced modules "online" regardless of driver result — CLOSED**

`firmware/gps_tracker/src/main.cpp:496-546` (`i2cRecoverTick()`): confirmed via `git diff`
between the prior verification commit (`7d85e34`) and the current tip (`f6a98bd`) that the
`i2c_bus::setOnline(m, true)` line was removed from all four switch cases
(DISPLAY/ACCEL/MAG/ENV). The `"[I2C] %s recovered"` log line is now gated on
`if (i2c_bus::online(m))`, which reflects whatever the driver's own `begin()` actually set
via its internal `i2c_bus::setOnline()` call (confirmed present and unconditional-on-result
in `accel_sensor.cpp:52`, `mag_sensor.cpp:108/123`, `env_sensor.cpp:33`,
`display.cpp:69/80/86`). `i2c_bus::clearReinit(m)` still runs unconditionally afterward,
matching the header contract ("success or not"). `grep -n setOnline main.cpp` confirms zero
remaining calls to `i2c_bus::setOnline` in `main.cpp` outside of comments — the forced-online
override is fully gone, not just narrowed.

**Gap 2 (CR-02) — `i2c_bus::present()` never refreshed post-boot — CLOSED**

`firmware/gps_tracker/src/i2c_bus.cpp:93-120` (`retryProbe()`): confirmed via the same `git
diff` that `s_present[addr] = true;` was added immediately after `s_boundAddr[idx] = addr;`,
right after a successful live `probeAddr()`. This means `display::begin()`
(`display.cpp:62-66`) and `mag_sensor::begin()` (`mag_sensor.cpp:83-89`) — both still reading
`i2c_bus::present()` unchanged — now see a cache that reflects live retry-probe results, not
just the one-time boot scan. A module absent at boot can now be selected/initialized once
`i2c_bus::tick()`'s round-robin retry proves the address answers.

**Regression check:** `git diff --stat` between the two commits touches exactly
`accel_sensor.cpp`, `display.cpp`, `env_sensor.cpp`, `i2c_bus.cpp`, `mag_sensor.cpp`,
`main.cpp` — no other file changed. No new `TBD`/`FIXME`/`XXX`/`TODO`/`HACK`/`PLACEHOLDER`
markers introduced (`grep` across the six touched files: none). `requestFrom` count in
`accel_sensor.cpp` is still exactly 2 (WHO_AM_I + 6-byte accel burst — D-07 untouched);
`delay(` count is still 0 in all five driver/bus files (the one `env_sensor.cpp` hit is
inside a comment referencing the pattern being avoided, not a real call) — D-05/D-06/D-07
and the non-blocking contract (truth #5) are unaffected by the fix.

**WR-01 (accel byte-assembly evaluation order) and WR-02 (dead per-driver `reinitDue()`
branches)** were also fixed in this same commit range and independently confirmed by reading
`accel_sensor.cpp:88-104` (six separate `uint8_t`/`Wire.read()` statements, sequence points
guaranteed) and by `grep -n reinitDue` across all four driver `.cpp` files (zero hits outside
comments — only `i2c_bus.cpp`'s implementation and `main.cpp`'s one live call site remain).
These were Warning-level findings, not blocking gaps, but their fix is consistent with and
reinforces the CR-01/CR-02 closure (a single, honest recovery path in `i2cRecoverTick()`).
