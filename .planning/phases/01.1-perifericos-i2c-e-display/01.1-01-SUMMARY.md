## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `Arduino.h` legacy `DISPLAY` macro collided with `I2cModule::DISPLAY`**
- **Found during:** Task 2 (first `pio run` compile attempt)
- **Issue:** `Arduino.h` defines a legacy `#define DISPLAY 0x1` (an old `Print`-class output-mode constant from early Arduino cores). Since `i2c_bus.cpp` and (later) `main.cpp` both include `Arduino.h`, every use of `I2cModule::DISPLAY` failed to compile with "expected unqualified-id before numeric constant".
- **Fix:** Added `#include <Arduino.h>` followed by `#undef DISPLAY` in `i2c_bus.h`, immediately before the `enum class I2cModule` declaration — Arduino.h's own include guard prevents the macro from being redefined later in the same translation unit, so this is a one-time, header-level fix rather than something every consumer needs to repeat.
- **Files modified:** `firmware/gps_tracker/src/i2c_bus.h`
- **Verification:** `pio run -e esp32-c3-supermini` and `-e esp32-devkit` both succeed (exit 0) with no macro-collision errors.
- **Committed in:** `9f2b4a5` (Task 2 commit)
