Apply the criteria in this exact order, returning the first failure:
  1. `f.fix_quality` below 1 → `REJECT_NO_FIX`. GGA fix quality 1 (standalone GPS) is the accept floor; neither target module produces DGPS/SBAS values under decision D-02, so requiring more would reject every real fix (Research Open Question 2).
  2. `f.age_ms` at or above `DEFAULT_GPS_FRESH_MS` → `REJECT_STALE`. This check is mandatory and is the single most important line in the module: the parser's location validity flag latches true on the first fix and is never cleared when lock is lost, so age is the only signal that a position has gone stale.
  3. `f.lat` and `f.lon` both exactly zero → `REJECT_NULL_ISLAND` (explicit null-island guard).
  4. `f.utc_unix` equal to 0 → `REJECT_TIME` (no trustworthy UTC date yet; Phase 2 records must be timestamped).
  5. `f.hdop` greater than `DEFAULT_GPS_HDOP_MAX` → `REJECT_HDOP`.
  6. `f.sats` below `DEFAULT_GPS_SATS_MIN` → `REJECT_SATS`.
  7. Warmup: while fewer than `DEFAULT_GPS_WARMUP_FIXES` consecutive fixes have passed checks 1-6, increment the streak counter and return `REJECT_WARMUP`. Any failure of checks 1-6 resets that streak to zero.
  8. Implausible jump: when a previous accepted fix exists, compute great-circle metres with the static `TinyGPSPlus::distanceBetween` helper (do not hand-roll haversine) and divide by the elapsed `mono_ms` delta; if the implied km/h exceeds `DEFAULT_GPS_MAX_PLAUSIBLE_KMH`, return `REJECT_OUTLIER_JUMP` without updating the stored last-accepted position (so one wild sample cannot poison the reference point).
On `ACCEPT`, store `f.lat`, `f.lon` and `f.mono_ms` as the new last-accepted reference and return `ACCEPT`. `reset()` clears the warmup streak and the last-accepted reference.

Rewire `src/main.cpp` so every snapshot returned by `poll()` goes through `FixGate::evaluate()` before anything else happens with it.
